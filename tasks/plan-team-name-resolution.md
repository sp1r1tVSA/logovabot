**Baseline зафиксирован:** `python -m pytest tests/ -q -p no:warnings --tb=no` → exit 0,
падений нет. Любое падение после правки — регресс, внесённый этой работой.

## Компоненты и направление зависимостей

```
config.CLUB_REGISTRY  (данные, статический список)
        │
        ▼
services/club_registry.py       ← НОВЫЙ; импортирует ТОЛЬКО config
   ├─ normalize_team_name()     ← переезжает из database.py
   ├─ TEAM_ALIASES              ← переезжает из database.py
   ├─ registry index            ← предпосчитанный normalized → canonical
   ├─ resolve_team_name_ex()    ← тиры 1–5
   ├─ resolve_team_name()       ← тонкая обёртка, обратная совместимость
   └─ teams_match()
        │
        ▼
database.py  ← реэкспорт всех четырёх имён; ни один вызов не меняется
        │
        ▼
~50 вызовов в handlers/, services/, api/  ← НЕ ТРОГАЕМ
```

Стрелки в одну сторону. `club_registry` не импортирует `database` — иначе цикл, а их в
проекте и так 15 (P4-6). Это и есть причина, по которой `normalize_team_name` и
`TEAM_ALIASES` переезжают вниз, а не остаются на месте.

## Порядок сборки

Вертикальными срезами: каждый шаг оставляет дерево в рабочем состоянии и проверяется
отдельно. Тесты идут **первыми** — до правки кода фиксируем и дефект, и то поведение,
которое ломать нельзя.

| # | Шаг | Почему здесь |
|---|---|---|
| 1 | Характеризационные тесты | Репро-кейсы красные, алиасы/каноны зелёные. Без этого невозможно отличить «починил» от «сломал по-другому» |
| 2 | `club_registry`: переезд + реестр | Механический перенос без смены поведения. Полный прогон здесь доказывает, что реэкспорт держит 50 вызовов |
| 3 | Тиры резолва | Здесь красное из шага 1 становится зелёным |
| 4 | `teams_match` | Тот же дефект, но отдельный шаг: у него свои вызовы и свой риск |
| 5 | Кэш | Оптимизация после корректности, не до |
| 6 | Интеграция с `get_standings` | Доказывает исходную жалобу: три клуба — три строки |
| 7 | Скрипт аудита | Нужен, чтобы получить реальный список с VPS |
| 8 | Заполнение реестра + страж дрейфа | **Блокирован шагом 7 и вашим прогоном на VPS** |
| 9 | Документация | `CLAUDE.md` сейчас описывает этот баг как known issue |

Шаги 6 и 7 независимы от 4–5 и могут идти параллельно, если понадобится.

### Чекпоинты

- **После 2:** `pytest tests/ -q` зелёный. Если нет — сломан реэкспорт, дальше не идти.
- **После 3:** репро-тесты зелёные, анти-регресс по алиасам зелёный, полный прогон зелёный.
- **После 6:** три строки в таблице. Это момент, когда исходная жалоба закрыта.
- **После 8:** аудит на VPS даёт 0 коллизий.

## Риски

| # | Риск | Вероятность | Митигация |
|---|---|---|---|
| R1 | Реэкспорт не покрывает какой-то способ импорта (`from database import *`) | Низкая | Шаг 2 = полный прогон + явный `__all__`-независимый модульный атрибут |
| R2 | **Ужесточение резолва ломает OCR-распознавание** | Средняя | Анти-регресс на **каждый** ключ `TEAM_ALIASES` пишется в шаге 1, до правки |
| R3 | `detect_teams_from_players` ([database.py:4964](../database.py:4964)) резолвит **отдельные слова** из подписи. Строгий резолвер вернёт слово сырым там, где раньше возвращал канон | **Высокая** | Тест на этот путь в шаге 3. Слово из подписи обязано резолвиться через алиасы (тир 2), а не через удалённую подстроку. Если тир 4 (префикс) не покрывает — расширяем алиасы, не ослабляем тиры |
| R4 | Циклический импорт при загрузке модуля | Низкая | `club_registry` импортирует только `config`; проверяется `python -c "import database"` в шаге 2 |
| R5 | Гонка за `league.db` при `-n auto` | Средняя | `uuid4`-суффиксы в фикстурах шага 6, как в `test_chat_division_scope.py` |
| R6 | Просадка производительности: резолв в цикле `get_standings` по всем матчам | Средняя | Предпосчитанный индекс (шаг 2) + LRU (шаг 5). Реестр на 80 имён вместо 16 увеличивает фаззи-перебор в 5 раз — кэш обязателен, а не опционален |
| R7 | Реестр не заполнен до шага 8 → резолвер работает на 16 именах | Высокая, ожидаемая | `CLUB_REGISTRY` по умолчанию = `KPL_TEAMS ∪ CLUBS`. Поведение не хуже текущего, тесты идут на подставном реестре |
| R8 | Порог 0.87 даст ложные отрицания на реальных именах | Средняя | Шаг 7 печатает распределение; реакция — новый алиас, **не** снижение порога (зафиксировано в спеке) |

R3 — главный риск этой работы. Он не про таблицу, а про OCR-поток: там резолв применяется
к произвольным словам подписи, где «строже» напрямую значит «меньше распознаём».
