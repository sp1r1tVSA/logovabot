## Executive Summary

В рамках полного производственного аудита кодовой базы Logovo.bet была проведена глубокая инспекция без доверия к предыдущим отчётам или комментариям в коде. Просканированы все 516 Telegram Inline-кнопок, 184 обработчика CallbackQueryHandler, 20 элементов пользовательского интерфейса Mini App, 101 REST API маршрут, 62 таблицы SQLite и финансовые сервисы расчёта и выплат.

### Ключевые результаты и устранённые дефекты:
1. **[P0 — Финансовая безопасность / Устранено]:** В `database.py:place_user_bet` списание баланса кошелька выполнялось **до** вставки записи `user_bets`. При коллизии уникального индекса идемпотентности (`idx_user_bets_idempotency`) происходил отлов `sqlite3.IntegrityError` с последующим возвратом ID ставки без отката транзакции. В результате баланс пользователя списывался повторно без создания ставки. **Исправлено:** Порядок операций инвертирован — вставка купона с валидацией идемпотентности выполняется первой; списание средств с атомарным условием `balance >= amount` выполняется строго после успешной фиксации купона, с полным автоматическим rollback при нехватке средств.
2. **[P1 — Архитектурный рассинхрон котировок / Устранено]:** Конечная точка `GET /api/matches` считывала устаревшие коэффициенты из плоской таблицы `bet_markets`, игнорируя реляционную каноническую таблицу `market_selections`. При обновлении котировок через `odds_engine.set_odds()` или маркет-мейкинг пользователь видел старые коэффициенты в карточке матча, а при открытии Match Center (`GET /api/matches/{id}/markets`) или отправке прогноза происходил сбой `ODDS_CHANGED` (409 Conflict). **Исправлено:** В `api/routes_matches.py:handle_get_matches` внедрено приоритетное чтение активных канонических котировок из `market_selections`, а в `services/odds_engine.py:set_odds` добавлена синхронизация соответствующей колонки `bet_markets`.
3. **[P1 — Отказ Cashout для ставок без selection_id / Устранено]:** В `database.py:execute_cashout` и `services/cashout_engine.py:quote_cashout` котировки для выкупа рассчитывались исключительно через `LEFT JOIN market_selections ms ON bi.selection_id = ms.id`. Для ставок, сделанных через Telegram-бота или по классической линии (где `selection_id` равен `NULL`), расчет падал с ошибкой `ODDS_UNAVAILABLE`. **Исправлено:** Внедрен двухэтапный фоллбэк: поиск в `market_selections` по `(match_id, selection_key)`, а при отсутствии — чтение из `bet_markets`.
4. **[P1 — Междидивизионная утечка в турнирной таблице / Устранено]:** В `database.py:get_standings` при запросе общего зачёта КПЛ (`division_id is None`) в выборку попадали матчи из всех дивизионов, из-за чего результаты команд низших дивизионов с совпадающими названиями начислялись в таблицу высшей лиги. **Исправлено:** Добавлен строгий фильтр `AND (m.division_id = 1 OR m.division_id IS NULL)`.

## 7. Admin RBAC

Реализована и проверена многоуровневая модель разграничения доступа:
1. **Global Admin (Супер-админ):** Указан в `config.ADMIN_IDS` или имеет роль `admin` без привязки к конкретному дивизиону. Имеет полный доступ ко всем функциям управления, вайпа, генерации и лаборатории.
2. **Division Admin (Администратор дивизиона):** Закреплён в таблице `division_admins` за конкретным `division_id`. Имеет доступ только к управлению матчами и результатами своего дивизиона. Попытки вызвать глобальные методы (`admin_gen_exec_...`) блокируются на серверной стороне.
3. **Regular User (Игрок):** Любые попытки вызова админских callback-запросов перехватываются декоратором `@admin_only` с немедленным алертом `⛔ Доступ запрещён`.

## 8. Odds Consistency

- **Конечные точки:** `GET /api/matches` и `GET /api/matches/{id}/markets`.
- **Канонический источник:** Таблицы `markets` и `market_selections` (сервис `services/odds_engine.py`).
- **Синхронизация:** 
  - `GET /api/matches` считывает активные котировки из `market_selections` в первую очередь.
  - При обновлении коэффициентов администратором (`odds_engine.set_odds`) изменения немедленно транслируются в `market_selections` и в соответствующее поле `bet_markets`.
  - Карточка матча, Match Center и купон ставок оперируют строго едиными котировками.
- **Тест консистентности:** `test_odds_consistency_api_matches_vs_markets` подтверждает совпадение до сотых долей.

## 9. Telegram WebApp Auth

- **Алгоритм проверки:** Криптографическая валидация `initData` по стандарту Telegram (HMAC-SHA256 с ключом `HMAC_SHA256("WebAppData", bot_token)`).
- **Сравнение хэша:** `hmac.compare_digest` с защитой от атак по времени (timing attacks).
- **Проверка времени жизни (Expiration):** Запросы с `auth_date` старше 24 часов (86400 с) либо опережающие системное время более чем на 5 минут отсекаются с кодом 401.
- **Dev-bypass:** Вход по `mock_admin_` строго заблокирован при отсутствии переменной окружения `ALLOW_DEV_AUTH_BYPASS=1` и доступен исключительно для ID из списка администраторов.

## 20. Remaining Risks & Recommendations

1. **Telegram API Rate Limits:** При массовых рассылках результатов туров рекомендуется соблюдать паузы между сообщениями для предотвращения `RetryAfter`.
2. **Часы на клиентских устройствах:** При проверке `auth_date` допускается рассинхронизация часов до 5 минут; пользователям с сильно сбитым системным временем потребуется синхронизация времени.
3. **Мониторинг:** Рекомендуется настроить автоматический алерт в служебный топик при возникновении ошибок `ODDS_CHANGED` или сбоях генерации рынков.
