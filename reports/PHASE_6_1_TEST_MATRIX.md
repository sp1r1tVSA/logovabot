# PHASE 6.1 TEST MATRIX — PRODUCTION ACCEPTANCE & RED TEAM AUDIT

This test matrix documents all adversarial attacks, expected behaviors, actual verified outcomes, statuses, and corresponding regression tests implemented during Phase 6.1.

| # | Area | Attack Vector | Expected Behavior | Actual Behavior | Status | Regression Test |
|---|---|---|---|---|---|---|
| 1 | Live Ingestion | Duplicate event replay with identical `provider_event_id` | Idempotent rejection with `"status": "duplicate"`, score unchanged | Score strictly preserved; duplicate logged without mutation | **PASSED** | `test_01_duplicate_event_replay_does_not_corrupt_score` |
| 2 | Live Ingestion | Scoring event arriving on `FINISHED` or `CANCELLED` match | Event rejected with `"status": "rejected"`, terminal score frozen | Rejected with terminal state warning, zero score alteration | **PASSED** | `test_02_event_on_finished_or_cancelled_match_rejected` |
| 3 | Live Ingestion | Malformed minute (`minute < 0` or `minute > 150`) | Rejected with `"status": "rejected"` | Rejected with malformed minute message | **PASSED** | `test_03_malformed_event_minute_rejected` |
| 4 | State Machine | Illegal lifecycle jump (`SCHEDULED` → `FINISHED`, `FINISHED` → `LIVE`) | Raises `InvalidStateTransitionError`, rollbacks transaction | Prohibited transitions strictly blocked with `InvalidStateTransitionError` | **PASSED** | `test_04_illegal_state_machine_transitions_rejected` |
| 5 | Market Safety | In-play bet on auto-suspended market (simultaneous with goal) | Immediate rejection inside atomic SQLite transaction | Rejected with "Рынок временно приостановлен", 0 coins debited | **PASSED** | `test_05_bet_on_suspended_market_rejected` |
| 6 | Odds Engine | Odds race attack (client sends stale 2.50, server moved to 2.00) | `HTTP 409` with `ODDS_CHANGED` and current server odds | Rejection with `ODDS_CHANGED` and authoritative odds | **PASSED** | `test_06_odds_race_attack_returns_409_odds_changed` |
| 7 | Limits & Payouts | Client sends `stake > MAX_BET` or `payout > MAX_PAYOUT` | Server authoritatively computes payout and rejects limits bypass | Rejections with `MAX_BET_EXCEEDED` and `MAX_PAYOUT_EXCEEDED` | **PASSED** | `test_07_client_cannot_tamper_with_payout_or_limits` |
| 8 | Betting Concurrency | 20 concurrent identical placement requests with same idempotency key | Exactly 1 bet inserted, exactly 1 coin debit, all threads get same `bet_id` | Exactly 1 bet placed, 1 transaction, wallet balance decremented once | **PASSED** | `test_08_double_bet_attack_with_idempotency_key` |
| 9 | Idempotency 2.0 | Reusing idempotency key with altered payload (e.g. higher stake) | Rejected with `409 IDEMPOTENCY_KEY_REUSED`, zero wallet debit | Rejected with `IDEMPOTENCY_KEY_REUSED`, zero debit | **PASSED** | `test_09_idempotency_key_reused_with_different_payload_rejected` |
| 10 | Wallet Concurrency | User with 1000 balance concurrently places two bets of 700 coins | Exactly one bet succeeds, second fails; balance >= 0 invariant holds | Exactly 1 bet placed, balance = 300, overdraft prevented | **PASSED** | `test_10_wallet_concurrency_prevents_overdraft` |
| 11 | Settlement Engine | 5 concurrent settlement execution loops on winning coupon | Exactly 1 payout transaction, balance credited exactly once | Exactly 1 payout credited, `WHERE settled_at IS NULL` atomic guard | **PASSED** | `test_11_concurrent_settlement_single_payout_only` |
| 12 | Refund Engine | Voiding already won bet or double-voiding a pending coupon | Cannot void settled bets; conditional update prevents double refund | `ValueError` raised on won bets and double voids; 0 double payouts | **PASSED** | `test_12_void_user_bet_rejects_settled_bets_and_double_voids` |
| 13 | Data Isolation | Historical team data, form, and stats queried across seasons | Strict season and division boundaries; zero cross-season stats leakage | Season 2 losses excluded from Season 1 intelligence queries | **PASSED** | `test_13_division_and_season_isolation` |
| 14 | API IDOR | User A requests User B's prediction slip details via IDOR | Returns `None` / `404` / `403`; private bet slip inaccessible | Query strictly scopes to authenticated user id; returns `None` | **PASSED** | `test_14_idor_get_user_bet_by_id_scopes_to_user` |
| 15 | Topic Isolation | Chat A `thread_id=100` vs Chat B `thread_id=100` | Composite key `(group_chat_id, message_thread_id)` routing | Cleanly separated into distinct division bindings in `TopicCache` | **PASSED** | `test_15_topic_isolation_different_chats_same_thread_id` |
| 16 | Auth Red Team | Tampered HMAC, missing `auth_date`, future `auth_date`, expired token | All invalid auth payloads rejected with `401 Unauthorized` | Signature and timestamp verification rejects all malicious payloads | **PASSED** | `test_16_auth_red_team` |
| 17 | Intelligence Math | Poisson distribution with 0 goals, edge cases, and value edge | $0.0 \le P \le 1.0$, edge computed accurately, no NaN or Inf | Math cleanly bounded, zero division handled, edge flags >3% points | **PASSED** | `test_17_poisson_probability_bounds_and_edge` |
| 18 | Leaderboard Threshold | User with 1 bet and 100% ROI on Capper Leaderboard | Excluded by `HAVING COUNT(*) >= min_bets` threshold (default 5) | Excluded from capper rankings; only users with $\ge 5$ bets qualify | **PASSED** | `test_18_leaderboard_min_bets_threshold` |
| 19 | Notification Anti-Flood | Dispatching same notification event 100 times to same user | Exactly 1 queued record; 99 rejected by DB UNIQUE constraint | 1 queued, 99 duplicates caught by `UNIQUE(user_id, event_type, source_event_id)` | **PASSED** | `test_19_notification_flood_attack_deduplication` |
| 20 | Database Integrity | Pagination boundary attacks (`limit=-1`, `limit=0`, huge limit) | Clamped cleanly without SQL errors or unhandled exceptions | Handled safely, user ROI strictly `None` when staked=0 | **PASSED** | `test_20_pagination_and_query_safety` |
