# Инструкция по полной очистке старого сезона (Logovo.bet)

Данная инструкция предназначена для безопасного и контролируемого удаления всех данных старого сезона на сервере перед запуском новой системы дивизионов.

---

## Что удаляется, а что сохраняется

| Категория | Что происходит |
| :--- | :--- |
| **Матчи и туры** (`matches`, `match_events`, `rounds`, `round_reminders`, `debt_reminders`, `cup_series`) | **Удаляются полностью (0 записей)** |
| **Рынки и котировки** (`markets`, `market_selections`, `bet_markets`, `odds_history`, `odds_movement`) | **Удаляются полностью (0 записей)** |
| **Ставки и купоны** (`user_bets`, `bet_items`, `saved_coupons`, `bet_audit_log`) | **Удаляются полностью (0 записей)** |
| **Лайв-данные и аналитика** (`live_events`, `live_statistics`, `live_match_states`, `predictions`, `prediction_snapshots`, `risk_alerts`) | **Удаляются полностью (0 записей)** |
| **Сезонная статистика** (`season_player_stats`, `season_snapshots`, `season_rules_config`, `season_rewards_catalog`, `season_reward_ledger`, `team_ratings`) | **Удаляются полностью (0 записей)** |
| **Команды и составы сезона** (`squad_players`, `teams`) | **Удаляются полностью (0 записей)** |
| **Старый сезон** (`seasons`) | **Удаляется полностью (0 записей)** |
| **Пользователи** (`users`) | **СОХРАНЯЮТСЯ 100%** (`telegram_id`, `username`, `role`, дата регистрации, варны). Сезонные поля сбрасываются: `team_name = NULL, league_name = NULL`. |
| **Балансы и кошельки** (`user_wallets`) | **СОХРАНЯЮТСЯ 100%** (баланс монет в кошельках не изменяется ни на 1 копейку). Сезонные счетчики ставок обнуляются (`bets_count=0, bets_won=0, total_wagered=0, total_won=0`). |
| **Финансовые транзакции** (`coin_transactions`) | **СОХРАНЯЮТСЯ 100%** (полная финансовая история депозитов, переводов, бонусов). |
| **Прогресс и достижения** (`user_progression`, `achievements_catalog`, `user_achievements`) | **СОХРАНЯЮТСЯ 100%** (уровни, опыт XP, титулы, рамки и полученные ачивки). Сбрасываются серии ставок: `current_streak = 0, best_streak = 0`. |
| **Архитектура дивизионов** (`divisions`, `division_topics`, `division_admins`) | **СОХРАНЯЮТСЯ 100%** (DIV_1..DIV_5 и админы готовы к привязке нового сезона). |
| **Системные настройки** (`system_config`, `tournaments`, `schema_migrations`) | **СОХРАНЯЮТСЯ 100%**. |

---

## Пошаговый регламент выполнения на сервере

### Шаг 0. Переход в директорию проекта и подтягивание кода

```bash
cd /root/logovabot
git pull
```

---

### Шаг 1. Создание резервной копии базы данных (Backup)

Перед любыми операциями обязательно создайте локальный бэкап файла базы данных:

```bash
# Создание бэкапа с временной меткой
cp league.db "league.db.backup_$(date +%Y%m%d_%H%M%S)"

# Проверка, что бэкап создан и имеет ненулевой размер
ls -lh league.db*
```

---

### Шаг 2. Запуск в безопасном режиме аудита (DRY-RUN)

Скрипт по умолчанию работает в режиме **Dry-Run**. Он не вносит никаких изменений в базу данных, а только сканирует таблицы и выводит сводный отчет:

```bash
python3 purge_old_season.py
```

*Или с явным указанием пути:*
```bash
python3 purge_old_season.py --db-path /root/logovabot/league.db
```

В консоли отобразится подробная таблица:
- Количество сезонных строк, которые будут удалены.
- Количество сохраняемых пользователей, кошельков и транзакций.
- Общая сумма сохраняемых балансов игроков.

---

### Шаг 3. Выполнение реального удаления (EXECUTE)

Когда вы убедились в корректности данных в отчете dry-run, запустите реальную очистку. Она выполняется в **единой атомарной транзакции** с автоматическим откатом (`rollback`) при любой непредвиденной ошибке:

```bash
python3 purge_old_season.py --execute
```

Скрипт выполнит:
1. Топологическую очистку всех сезонных таблиц (Child-first).
2. Отвязку дивизионов `DIV_1`..`DIV_5` от старого сезона.
3. Сброс сезонных полей в `users`, `user_wallets` и `user_progression`.
4. Автоматическую валидацию целостности:
   - `PRAGMA foreign_key_check`
   - `PRAGMA integrity_check`
   - Сверку балансов игроков до и после (0 расхождений)
   - Проверку целостности дивизионов.

---

### Шаг 4. Проверка состояния базы данных после очистки

Скрипт автоматически выполняет все проверки, но вы также можете выполнить контрольные SQL-запросы вручную:

```bash
sqlite3 league.db "
SELECT '1. Сезонов осталось: ' || COUNT(*) FROM seasons;
SELECT '2. Матчей осталось: ' || COUNT(*) FROM matches;
SELECT '3. Ставок осталось: ' || COUNT(*) FROM user_bets;
SELECT '4. Пользователей сохранено: ' || COUNT(*) FROM users;
SELECT '5. Кошельков сохранено: ' || COUNT(*) FROM user_wallets;
SELECT '6. Сумма монет: ' || SUM(balance) FROM user_wallets;
SELECT '7. Дивизионов сохранено: ' || COUNT(*) FROM divisions;
PRAGMA foreign_key_check;
PRAGMA integrity_check;
"
```

**Ожидаемый результат:**
- Сезонов: `0`
- Матчей: `0`
- Ставок: `0`
- Пользователей: то же число, что и до очистки
- Сумма монет: та же сумма, что и до очистки
- `foreign_key_check`: пусто (0 строк)
- `integrity_check`: `ok`

---

### Шаг 5. Перезапуск бота (при необходимости)

```bash
systemctl restart logovabot
```

После этого база данных находится в чистом, консистентном состоянии и полностью готова к созданию нового сезона и настройке дивизионов.
